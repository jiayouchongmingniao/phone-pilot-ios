# 原生触控校准

2026-11-03。已实现三端代码，真机验收待完成。当前仅支持 iPhone 16e 竖屏 390×844 点。

## 目的与边界

用户实测 ScreenCaptureKit 整屏共享没有鼠标指针，因此生产路径停止调用灰圈检测。iPhone 专用空白页通过 UIKit 接收实际点击，将视图坐标转换成当前屏幕的点坐标；不使用截图像素或安全区坐标，也不能接收微信等其他 App 的触摸。

校准固定 HID 算法 `home-yx7-grid-v3`：30 次归位报告，然后只用完整的 7 单位报告先移动 Y 再移动 X，不发送定位末尾不足7单位的报告。共九点：先用单位量 (84,126)、(196,406) 粗测，再按粗映射探测屏幕点 (50,90)、(340,750)、(50,750)、(340,90)、(195,420)，仅用这五个新样本做分轴线性拟合。所有定位单位量均从连续反解值直接取最近的7倍数，粗测、拟合、验证和日常定位使用同一规则。最后在原始屏幕目标 (300,700)、(310,160) 检查每轴实际误差不超过 6 点，不把验证目标改成量化后的预测落点。拟合样本的实际范围必须包住两个验证目标并留出6点余量，验证所需单位量也必须处于采样单位范围内；否则停止，不用外推替代覆盖。粗测和失败的验证点均不加入最终拟合。

14单位版本实测比例约0.87点/单位，完整报告相隔约12.18点，仅取最近格的最坏量化误差约6.09点，已超过6点门槛。最新独立点还存在约2.59点纵向模型残差，不能只靠零训练RMS判断精度。本版把完整报告缩为7单位，给误差留出余量，但iOS加速响应会随步长改变，不能沿用旧比例，也不能把7单位理论精度当作真机结果。正常定位若最近格的预测落点与原目标任一轴相差超过6点，仍直接停止；独立验证仍以真实触点判断。需要新版圆屏与Mac共同更新并重新校准；iOS需支持下述5秒窗口声明，具体TestFlight构建与部署记录见validation.md。

只有所有回报及独立验证均通过才缓存；6 点是当前开发验收阈值，不是已证明的精度。九点沿用现有握手和120秒总期限。更细步长增加移动报告数，定位数组容量为512；当前完整报告及位移上限最多需要458份定位报告，名义耗时约4.58秒，仍受10秒USB任务期限约束。额外静态内存占用及真实精度以构建和真机验收记录为准。

开始由用户在 iPhone 手动触发，保持整屏共享、校准页前台、圆屏 USB 接 iPhone，并遵守“请勿触碰屏幕”。UIKit 的实际 `direct` / `indirectPointer` 类型会显示并记录在内存中；AssistiveTouch 是否能与手指可靠区分仍待实测，不能以 `.direct` 回报证明来源。页面检测多触摸、超过4点位移和迟到事件会取消。

## 握手

- 手机 `POST /calibration`，使用 phone Bearer token。`begin` 带页面 UUID、`geometry:[390,844,"portrait"]`及整数`touch_window_ms:5000`；缺失/错误窗口声明拒绝开始，防止与旧2秒窗口客户端混用。其余操作带会话 id，操作具体探针时还带 probe。所有坐标均为屏幕点。
- 圆屏配对必须声明 `native_touch_v1`。`GET /next` 的顶层 `calibration` 控制包与模型业务动作互斥；校准不占业务任务10步额度，也不能被模型发起。
- 还必须声明 `hid_delivery_v1` 与 `pointer_grid7_v1` 才允许开始校准。两类移动命令（校准move与普通定位move）均携带 `report_units:7`，新圆屏拒绝缺失或错误步长，避免新旧固件/服务混用。旧算法映射不复用。`moved/clicked` 附加 `usb`：`planned/submitted/completed/error/duration_ms/min_gap_ms/max_gap_ms`。计数分别为计划、已提交、收到成功传输回调的 HID 报告数；间隔是相邻实际提交起点之间的毫秒数。移动计划数必须为 `30+dx/7+dy/7`，点击必须是按下和释放两份报告。成功回报必须计数全齐、error=none、最小间隔至少10ms且耗时一致；缺失或矛盾会停止。状态仅保留白名单数值及错误枚举，不保存报告原文或身份字段。
- 一点的顺序：`move → moved → arm → armed → permit → click → point + clicked`。两份完成回报可任意先后到达，必须都对应当前唯一 probe 才推进。
- 手机每250ms串行轮询，确认整窗触摸空闲才先本地 arm，再上报 armed；许可和触摸可能先于 armed HTTP 响应，因此事件在本地绑定当时的会话和 probe 后暂存。
- 圆屏 `POST /calibration/device` 的操作为 `moved / permit / clicked`。移动和点击不排在同一 HID 队列；每条命令先记账再执行。重复许可会拒绝并终止，不重发点击。
- 手机请求/资源超时2秒；圆屏校准 HTTP 3秒。圆屏许可往返超过1秒不点击。Mac仅在成功验证并接受moved后3秒内发出唯一permit，poll/armed不能续期；这个锚点早于手机收到arm并打开本地接收窗口。手机本地接收窗口统一为5秒，许可后Mac仍须在2秒内收到有效触控。因此及时触点的接收时刻不晚于moved+5秒，也不晚于手机本地arm+5秒，避免早开窗被准备过程耗尽。旧手机不满足5000声明门，不能开始。许可时手机心跳仍需不超过0.8秒、整个阶段心跳不超过2秒、每点不超过15秒、总共120秒。
- 仅当触控已及时接受时，允许同一probe的USB回报最迟在许可后5秒到达，心跳不延长该截止；回报仍须统计完整且成功才推进。此回报等待不重开触控窗口，不补发点击。iOS仅在尚未缓存有效触点时检查本地arm等待超时，避免窗口内收到的点在稍晚的轮询续体中被丢弃；收到点时仍验证同一身份、页面及5秒本地接收期限。Mac在全局锁外读取并解析截图/校准HTTP请求体，提交前在锁内再次鉴权，防止慢上传阻塞校准心跳，也拒绝读取期间已被轮换的旧令牌。
- 圆屏仅在校准期间将轮询等待设为50ms，普通任务保持400ms。进度UI在申请permit之前更新；实际提交USB前再检查许可年龄与校准总期限，中间不再获取UI锁或发起网络请求。成功permit回包若已超过1秒，先停止且不点击，最多上报一次`op=abort,reason=permit_expired,elapsed_ms`，失败不重试，也不覆盖本地停止原因。Mac只接受同probe且确曾许可、尚无成功clicked回报的合法停止信息；已失败会话可补诊断，不能恢复或发布映射。
- Mac只保留最多九行每probe相对开始时间（毫秒）：首次生成move/click命令，以及moved、armed、permit、point、clicked、cancel请求到达。未发生为null，不记录轮询明细或身份字段。请求时间不代表接受，命令时间不代表设备收到；首次失败冻结当时phase、最后操作、心跳/许可年龄及是否已有point/clicked，后续cancel不能覆盖。仍未直接测量iOS本地arm年龄或触摸回调延迟；没有abort不证明没有本地停止。
- 点击发出后无法原子撤回。因此前台撤销只能阻止尚未获许可的后续点击，页面失去前台与已许可 HID 发出之间存在很小的时序窗口。不会预排剩余探针。

发送失败不重发相对位移，也不继续剩余 job；未决或失败传输锁定该次应用运行。任务结束后保留统计并调用既有 USB 停止流程断开，避免已按下却未确认释放的输入一直保留；需要返回 Yay 重开。停止过程增加并发同步，故障断开与用户退出同时发生时只卸载一次，两方返回前都需完成引脚交还。USB 完成回调只证明传到主机，不能代替 UIKit 实际触点或证明 App 操作结果。正常退出恢复、故障时断开和实际移动稳定性须在新版固件上单独验收。

## 日常复用

校准只保存在 Mac 内存并绑定当前配对、屏幕点尺寸/方向及算法版本。普通任务结束保留；停止共享、手机或圆屏重新配对、Mac重启、任意几何变化立即清除。即使随后转回原几何也不复活。重新开始校准清除旧映射，失败不回退旧值；改变 AssistiveTouch 跟踪速度后应主动重校准。

圆屏先请求一次 `/check` 做移动前检查。画面和当前映射有效时，Mac只创建尚未执行、尚未授权的定位任务；此时不能报告点击完成。`POST /pointer` 再提供唯一一次目标移动；USB回报后必须等待更新的帧、轮询获得ready，再次 `/check` 检查原目标画面才授权点击。重复预检不会再次放行或重建任务；无映射、重复移动回报或新帧缺失不能授权。校准因几何变化失效时，已有定位任务也永久失败，转回原尺寸不能继续。诊断明确标为 `calibration_verified=true`、`landing_observed=false`，不声称看到了其他 App 中的鼠标落点。任务成功仍须依据执行后的新画面及目标证据判断。

Jev选择的`app_icon`若在移动后出现画面变化，成功的移动回报仍先登记，仅建立新帧屏障，不授权点击。首次ready之前复核：Claude读取同一张移动后新帧，Jev重新判断；如果复核期间当前帧又变化，仅允许一次丢弃旧结果并等待比冲突帧更新的图像，再完整重新识别和判断；第二次变化停止。若首次框含原点击点但6点余量不足，且审查帧与当前帧一致，也可共用同一预算等待新帧重新完整识别；首次框不含原点时直接停止。首次失败帧和重新识别帧都必须在模型返回及最终检查时分别与当前帧通过比较，禁止逐次小变化累积绕过检查；二次识别来自同一模型，不构成独立验证。结果仍须为同一App图标，原点击点连同6点边距须在新图标框内。坐标和USB移动均不重发；提交时复验任务、动作、配对、校准、几何、共享与原60秒期限，已审查帧还须与当前画面通过原像素检查，才替换比较基准。最后`/check`继续检查该基准；首次ready后不再启动复核。两次模型请求分在两次轮询中、都在状态锁外，并发请求只等待。输入、发送、普通点击、翻页及移动前检查不获得此例外。持续变化的页面仍可能停止；复核不等于忽略所有桌面动画。

移动后Jev复核只问一个`icon_available` Noul：新观察是否仍确认本地已选App的启动图标可用，返回布尔判断，不再选择done/swipe/search或重新评估完整用户意图。Noul门槛保持0.8；Claude可见性yes和0.9置信门槛仍独立检查。首次Jev规划另行把原始打开意图与图标可用性拆为两项，门槛分别0.9和0.8；移动后仍只复核已选图标。Jev收到的是Claude的结构化观察，并非独立看图，两个分数不能相乘作为点击准确率。问题范围依据[TypeSafe Noul文档](https://docs.typesafe.ai/primitives/noul)的单命题建议收窄，真实模型表现仍须验收。

App 图标点击和主屏翻页沿用无需圆屏确认的约定；发送仍需要具体收件人、文字和明确确认。付款、删除不支持。坐标与业务文字不在校准状态接口中混用；默认不保存原始画面或音频。

翻页拖动也使用7单位完整报告，并按新校准比例把210点水平位移量化为7的倍数，避免用7单位比例驱动旧14单位执行器。按住拖动与无按键定位的实际响应是否一致、拖动终点及翻页效果仍须真机验证。

## 验收

自动测试覆盖九点协议、粗测与拟合分离、覆盖不足、双回报先后顺序、独立点偏差、重复/迟到/错误身份、后台取消对应协议、共享/设备失联、几何变回仍失效、缓存复用及新帧屏障。HTTP 测试只启动独立回环服务，未接真实演示服务或调用云API。最新运行结果见 validation.md。

圆屏：最新发送层修正及构建/部署进度见 validation.md。底层卸载及引脚交还顺序保留，停止入口增加并发同步；7单位版本正常返回 Yay 后串口恢复已实测。异常崩溃恢复仍未解决。

iOS：Swift 6 本地语法检查及 GitHub Xcode 编译通过；5秒窗口修复已发布至TestFlight build28并进入原内部测试群组，需配合新版Mac服务。发布结果见 validation.md。语法和编译不能代替 UIKit 布局、触控事件和实际精度验收。

真机顺序：

1. 安装包含校准页的 iOS 新版，手机/圆屏用当前配对码连接，恢复整屏共享。
2. 圆屏USB接iPhone，在手机打开安全校准页并点开始，保持不碰屏幕；确认九点完成，查看实际触控类型及服务缓存状态。
3. 关闭校准页回主屏，连续两次“打开微信”（两次之间回到主屏）；确认后续任务不重做九点，并核对真正打开的是微信。
4. 没有图标时验证主屏翻页/搜索；误开、旧画面或结果不明时应停止或重新观察，不沿用旧坐标盲点。
5. 验证取消/后台/断网及停止共享后不能继续点击；另验证输入和发送确认。第2项未通过前不将后续动作称为验收完成。
