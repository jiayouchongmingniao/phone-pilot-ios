# Phone Pilot 开发演示

此版本仍在开发中。iPhone、圆屏和 Mac 必须连接同一个可信的 Wi-Fi。局域网连接使用明文 HTTP；不要在公共网络运行。录音由阿里云 qwen-audio-3.1-asr-flash 转写；Claude Haiku 5.5 理解复杂说法，并识别屏幕目标和位置；TypeSafe Jev 1.14.0 根据结构化画面证据选择动作。Jev 失败时不会改由 Claude 决策。每个任务最多执行 10 步。

## iCTRL 执行层

现在主要用圆屏直连：圆屏自己调用 Qwen，通过 Wi-Fi 操作手机，运行时不需要 Mac。支持的语音指令、微信发消息的规则和验证状态见 [ictrl-integration.md](ictrl-integration.md)。下面这段是经过 Mac 的备用路径。

设置 `EXECUTOR=ictrl` 和 `ICTRL_HOST` 后，Mac 通过手机上的 iCTRL runner 打开 App 和输入文字，不需要屏幕共享、校准和 USB 键鼠。默认仍走下面的 HID 路径。步骤和限制见 [ictrl-integration.md](ictrl-integration.md)。

## 真实点击校准（新版，待真机验收）

当前 iPhone 整屏录制不包含鼠标指针。坐标执行已改为 `native_touch_v1`，并要求圆屏提供 `hid_delivery_v1` 的逐报告传输确认及 `pointer_grid7_v1` 的7单位完整报告，不再调用灰圈检测；旧固件不能开始新版校准。校准入口在 iPhone「手机遥控 → 打开安全校准页」。圆屏连接 iPhone 后，用户手动点开始并保持页面前台，请勿触摸屏幕。

iPhone 需更新至 TestFlight build 28，并重启 Mac 服务加载配套时限。手机本地接收窗口为5秒，开始时声明 `touch_window_ms=5000`；Mac拒绝旧客户端。Mac只在成功接受移动回报后3秒内授予点击许可，心跳不延长准备期限，以免正常点击在手机窗口过期后才获准。当前7单位圆屏固件无需再次更新。

每个探测先移动，手机确认整窗无活跃触摸并启用当前探针，圆屏再请求一次性许可并点击。UIKit 把实际触控转换成全屏点坐标；回报与 USB 完成回报按会话及探针编号关联，顺序可颠倒。有效触控仍须在许可后2秒内到达；已收到有效触控时，仅USB回报可等到许可后5秒，仍须完整确认才推进，不重复点击。先用两点粗测，再采集覆盖屏幕的五点做拟合，最后两个独立验证点每轴误差不超过 6 点才缓存，共九点；采样必须实际覆盖验证范围。缺失、重复、迟到、多触点、拖动、后台、共享停止或几何变化会停止；不会回退视觉猜指针或重发点击。`.direct` 事件仅记录类型，不能证明来源为 HID，因此校准须处于明确请勿触碰的受控环境。

同一配对会话之后复用映射：回原点、完整的 7 单位报告先 Y 后 X、移动到目标，等待更新的帧并检查原目标画面。校准、日常定位和翻页拖动都将位移取最近的7倍数，不发较短的末包；目标量化后预测误差超过6点时停止，不宣称任意坐标都能达到6点精度。7单位会改变iOS加速响应，必须使用新版圆屏重新实测，不能复用旧14单位映射。诊断区分 `calibration_verified=true` 与 `landing_observed=false`；在微信等其他 App 内不能读取真实触控落点。实际是否完成仍以操作后画面核实。普通任务结束不清缓存；重新配对、停止共享、重启或任何屏幕几何变化会失效。跟踪速度改变后应重新校准。最多 10 个业务动作，校准仅在自己的专用空白页执行，与业务任务互斥。

具体握手、验收和限制见 [native-calibration.md](native-calibration.md)。方案参考 [ESP32 iPhone Agent / Open iPhone Use](reference-review.md) 的实际点击探针及 [Mika](mika-review.md) 的结果分层；来源许可见 [third_party/README.md](third_party/README.md)。历史灰圈实现保留为未调用的参考代码与合成图测试，不能用其测试证明真机落点。

打开App时，若定位后画面变化，Mac可用新画面复核同一图标；复核期间再次变化时，最多等待更新帧再完整复核一次。若首次复核框包含原点击点但不足6点边距，且复核帧与当前帧一致，也可共用这一次预算重新识别；首帧作为额外固定基准，直到最终点击检查都须与新画面一致。第二次仍须满足完整6点边距；点不在首次框内或画面不一致时停止。重试不会重复移动或重新校准，且多次判断来自同一模型，并非独立验证。首次放行后再变化仍停止，发送和其他动作保持原检查。此修复需重启Mac服务加载，当前iPhone build28和7单位圆屏无需更新。

在 Mac 的终端中启动服务。密钥在终端中静默输入，不要提交或发到聊天中；已在同一终端导出的密钥无需重输：

```zsh
cd phone-pilot-ios
source "$HOME/Library/Application Support/PhonePilot/local.env"
python3 -m venv demo/.venv
demo/.venv/bin/python -m pip install -r demo/requirements.txt
read -s 'ANTHROPIC_API_KEY?Anthropic API key: '; export ANTHROPIC_API_KEY; echo
read -s 'DASHSCOPE_API_KEY?DashScope API key: '; export DASHSCOPE_API_KEY; echo
read -s 'TYPESAFE_API_KEY?TypeSafe API key: '; export TYPESAFE_API_KEY; echo
export VISION_PROVIDER=jev
demo/.venv/bin/python demo/server.py --bind "$(ipconfig getifaddr en0)"
```

Pillow 用于在内存中比较解码后的画面，pypinyin 用于本地拼音转换。首次运行或依赖更新时安装 requirements；重启时在原终端执行最后一行即可。原来的 `python3 demo/server.py ...` 命令也可使用：当前解释器缺少 Pillow 或 pypinyin 时，会自动转到已存在的 `demo/.venv`，保留启动参数和环境变量，不自动安装依赖。测试命令为 `demo/.venv/bin/python -m unittest discover -s demo -v`。

默认使用阿里云北京地域的 `dashscope.aliyuncs.com`。目前此 Mac 对该旧域名的 TLS 握手超时。若使用北京业务空间的专属域名，在启动服务前运行 `export DASHSCOPE_BASE_URL=https://<WorkspaceId>.cn-beijing.maas.aliyuncs.com/api/v1`（将占位符替换为业务空间 ID）；密钥和服务地域必须一致。本机配置还将 Qwen 请求绑定到 `en0`，并使用系统 CA 证书；仅验证了网络和 TLS，还需新密钥做实际识别。服务输出 Mac 地址及配对码；在 iPhone 和圆屏各输入一次。每次重启服务要重新配对。

打开 iPhone App，输入地址和配对码，选择整个屏幕。圆屏填写相同地址和配对码并连接。圆屏按住侧键说话。新固件直接执行已核实的 App 图标点击和主屏翻页；普通点击及发送仍需圆屏确认。发送确认和中文拼音输入均需要最新固件与协调服务，尚未经真机验证；不能确认候选词或画面变化时应停止。用 Ctrl-C 停止 Mac 服务。

离开圆屏应用必须通过双击侧键打开应用环，返回 Yay；不可假定异常崩溃后 USB 一定恢复。运行时设备 USB 是 iPhone 键鼠，设备串口和刷写暂不可用。

停止共享后，iPhone 可用当前配对码重新连接。如果旧应用没能向 Mac 报告停止，连续超过 15 秒未收到画面后也允许用正确配对码重连；首次配对等待选择屏幕时同样保留 15 秒。新手机令牌使旧令牌失效，旧画面和未完成任务会清除，圆屏连接不受影响。持续正常上传时拒绝重复配对；旧任务迟到的模型返回也不会作用于重新连接后的任务。此行为需要加载新版协调服务，旧服务仍会拒绝未收到停止通知的手机重连。

圆屏连接中断后，连续超过 60 秒没有携带有效令牌的请求，允许用当前正确配对码重新连接；旧圆屏令牌和未完成任务会清除，手机共享保持原连接。该等待时间长于单次视觉请求，避免把正常等待模型的圆屏误判为失联。

状态中的 `paired` 表示已登记的角色，不能单独证明设备在线；`device_age_ms` 是距圆屏上次有效请求的时间，手机是否仍在上传需检查 `frame_age_ms`。

排查时可读取 `GET /status`，请求头为 `Authorization: Pair <当前配对码>`。只返回连接角色、帧数与帧龄、任务状态、密钥是否配置、最近一次 API 错误，以及 `last_decision` 中的动作类型和阶段；不返回密钥、令牌、画面或转写内容。`frame_changed` 表示动作因画面变化被拦截，`capture_stale` 表示没有新鲜画面，`proposed` 表示已下发，`executed` 只表示圆屏报告执行成功，不能代替视觉验收。任务失败原因保留到下一次任务或停止共享；最近一次动作阶段保留到下一次任务。Mac 终端也会输出供应商 HTTP 状态和错误类型，不记录原始响应正文。一次 API 错误记录保留到下次语音请求或服务重启。

`frame_difference` 仅报告差异像素数量、外接矩形（图像像素坐标）、最大 RGB 通道差、通道差大于 8/32 的像素数量、是否排除状态栏及几何/解码错误，不返回原图或转写。`strong_bbox_px` 是通道差大于 8 的区域；`pixel_tolerance` 是本次正文检查的容差，`body_max_channel_delta`、`body_pixels_over_tolerance` 区分正文刷新及超过容差的变化。`protected_region_changed_pixels` 仍统计保护区所有非零差异，新增 `protected_region_pixel_tolerance`、`protected_region_pixels_over_tolerance` 和 `protected_region_max_channel_delta` 区分目标区域的轻微刷新与超限变化；`small_refresh_exception` 标记是否使用目标区外少量像素余量。该诊断保留到下一次任务或下一次画面比较；它能定位拦截发生在哪一块，但不能单独识别画面内容。

本地诊断工具 `swift demo/ocr_probe.swift <图片路径> 微信` 使用 macOS Vision，只返回与目标标签完全相等的文字框、置信度和图片像素尺寸；零个或多个框都不能作为单一目标。工具不调用模型或控制手机，不参与生产点击，也不保存图像；图片像素坐标不等同于屏幕点。其真实 iPhone 主屏效果和文字框与图标的空间关系尚未验证。

`last_execution` 保留最后一次收到执行回报的动作类型、坐标/方向、图像尺寸、屏幕点尺寸和执行回报布尔值，后续完成/协助判断不会覆盖它；下一任务开始时清空。它不包含转写、输入文字或收件人，执行回报也不代表点击命中。 App 图标复核的 `pointer_diagnostic` 可保留首次和复核框的屏幕点边界与帧序号、点击点到四边的距离、6 点余量、未通过的边及是否完全包含；坐标仅作显示时取三位小数，授权比较仍使用未舍入值。复核重试会清除旧的复核框信息；因边距不足而重试时，另保留首个未通过框的纯数值快照。不返回图像、指令或图标文字；框来自模型观察，不证明指针实际落点。

`perception_diagnostic` 记录 Claude 的画面识别耗时及各候选条件是否成立、置信度，不暴露坐标或原图。`vision_diagnostic` 记录 Jev 的阶段、耗时、候选概率、Choice 置信度及 Noul 条件分数。`gate` 区分 `model_assist`、`choice_confidence`、`choice_probability`、`intent_validity`、`action_validity`、`box_confidence`、`perception_validity`、`passed`、`invalid_response` 和 `request_failed`；其中框及画面证据的置信度来自 Claude。只接收本地已知候选名、固定状态及有限的 0～1 数字，不记录截图、转写或响应正文；任务结束后保留到下一任务开始，迟到的旧任务结果不得覆盖新任务诊断。`action_validity_threshold` 记录所选动作实际使用的条件门槛；App 图标点击和 App 打开完成判断另有 `intent_validity` 和 `intent_validity_threshold`；`step_limit` 显示当前任务动作上限。

默认 `VISION_PROVIDER=jev` 使用 [TypeSafe System One API](https://docs.typesafe.ai/api/system-one)：Claude 仅返回本地候选条件的视觉证据和归一化目标框，不选择动作；Jev 接收这些结构化证据，用 Choice 选择一步、Noul 核对原始指令与动作条件。截图只发往 Anthropic，Jev 不再直接识图。坐标只能来自本机校验过的 Claude 目标框，Jev 不能另造坐标、输入文字或收件人。Choice 概率 ≥ 0.9、Choice confidence ≥ 0.8；打开 App、点击 App 图标和主屏翻页的动作 Noul 门槛为 0.8，输入、发送及其完成判断的 Noul 门槛为 0.9。App 图标点击把原始指令是否仅要求打开该 App（Noul ≥ 0.9）与图标是否可用（Noul ≥ 0.8）分开判断；App 完成时 Jev 仍需选择 done 并以 Noul ≥ 0.9 核对原始意图，程序直接要求 Claude 前台界面结论为 yes 且 confidence ≥ 0.9，不再让 Jev 对同一结构化观察单独重复评分。Jev 不独立查看截图，不能仅凭 USB 执行回报判定完成；移除重复评分门后，Claude 与 Jev 仍可能共同误判。否定、引用和附带输入/发送的复合请求不能只执行打开部分。Claude 对所选动作的视觉条件还必须明确为 yes 且 confidence ≥ 0.9。Claude 的 confidence 表示对 yes/no/unclear 分类的确信程度，高置信 no 表示确信条件不成立。按用户要求，新固件对 App 导航省略圆屏确认，执行前仍请求最新画面检查；其他点击和发送继续确认，坐标校验不变。这些门槛尚未经真机校准，不代表成功率。任一模型结果不明确、格式错误或坐标越界均停止。

简单命令本地解析；无法匹配的自然语言通过 Claude 结构化输出提取单个意图，只发送转写文本。提取出的 App 必须在本地清单中，输入文字及收件人必须来自原始转写；不得改写文字或丢弃复合指令中的其他目标。指令理解、画面识别、Jev 判断分别使用独立轮询，避免云请求等待相加。画面证据始终绑定识别时的原始帧，执行前与最新画面比较；执行后清除旧证据并等待新帧。保留显式 `VISION_PROVIDER=anthropic` 仅供旧模式回归；它不是自动后备路径。

圆屏在当前会话内显示“识别：”原始转写和“指令：”解析结果，均用 28 px 字号，长行横向滚动；解析失败显示“未能解析”，原转写保留到下一次录音。发送确认期间隐藏两行反馈，展示收件人与内容，确认结束后恢复。显示文字经已配对设备的 `/audio`、`/next` 返回，不加入 `/status` 或日志。显示最多保留前 160 个字符并标明省略，执行仍使用完整转写。新版声明 `speech_feedback_v1` 和 `app_navigation_auto_v1`，用于核对部署版本；旧固件会忽略新增字段。

当前支持清单内 App 的打开（例如「打开微信」）、当前页面的单次输入（例如「输入hello」「输入你好」），以及当前聊天中的明确发送（例如「给张三发送hello」）。不自动寻找联系人，不执行含多个目标的复合指令。英文仅允许固件支持的字母、数字、空格及 `,.-/`；中文只接受最多 14 个汉字、可唯一解析的无声调拼音，并要求屏幕确认拼音键盘、完整候选词和提交后的文字。发送前必须核实当前聊天收件人和完整草稿，再经圆屏确认。中文输入仍未完成真机验收。执行历史只在内存中保留，避免重复输入或发送。

主屏翻页需要 `home_swipe_v1` 及新版真实触控校准能力（`native_touch_v1`、`hid_delivery_v1`、`pointer_grid7_v1`）；旧固件只可继续输入和使用 Spotlight，坐标点击/发送/翻页需要新版校准。仅允许在确认的主屏上、未找到目标且下方拖动路径为空白时向左或向右翻页。首步由 Jev 选择方向，之后沿同一方向累计最多执行 6 次翻页，避免来回循环。Claude 确信图标缺失且至少一个翻页方向安全时，Mac 从候选中移除 Spotlight 搜索，再由 Jev 选择方向或停止，不直接合成翻页。到达边界、路径不可用或六次预算用尽时仍可选择 Spotlight；缺乏可靠证据则停止求助。执行成功回报不等于已经换页，真实翻页效果仍需验收。每次翻页都计入 10 步上限，并需最新画面和起点检查。目标拖动路径为 iPhone 16e 竖屏 y=700、x=300→90 或 90→300，HID 移动量使用实测比例换算；尚待真机验收，不能用于 Spotlight、App 内、图标编辑模式或有遮挡的桌面。

真实触控校准需要包含校准页的新版 iOS；build 12 仍可共享，但无法完成原生校准。Jev 接收原始指令及结构化视觉证据。`/status` 的 `vision_provider`、`intent_provider`、`device_capabilities` 及三项 `*_key_configured` 可用于检查配置；密钥存在不等于已通过 API 鉴权。

上游断开连接、响应读到一半、连接重置及超时会转为供应商连接错误。仅已成功点击 App 图标后的完成画面识别遇到明确传输断开，才按下面的单次复核预算重试；其他情况停止并向圆屏返回正常 JSON 错误，不留下悬挂任务或直接中断请求线程。重试可能产生第二次模型调用费用。错误详情只保留异常类型，不记录响应内容。

实测 iPhone 自动锁屏/息屏会停止共享。演示前在「设置 → 显示与亮度 → 自动锁定」临时选择「永不」，结束后恢复原设置；共享中不要手动锁屏。如选项灰色，检查低电量模式是否打开，它会将自动锁定设为 30 秒（[Apple 说明](https://support.apple.com/zh-cn/101604)）。当前 App 没有自动防锁屏功能，不能保证锁屏后继续捕获。Apple 的 [ScreenCaptureKit 示例](https://developer.apple.com/documentation/screencapturekit/capturing-screen-content-on-ios)说明了切到其他 App 后继续捕获，但没有承诺锁屏时继续。停止后需要重新共享。没有新鲜画面时，不启动任务；执行过程中画面过期则停止。即使 `capture_stopped` 是 false，也必须检查帧龄：未收到停止通知不代表画面仍在更新。

动作下发时检查最新收到的画面是否在 5 秒内。打开 App 使用 Spotlight 键盘宏，不依赖截图坐标，允许期间画面更新；其他执行动作比较解码后的 RGB 像素、尺寸及方向，JPEG 附带注释等编码信息变化不再视为画面变化。即便两帧字节完全相同，也先校验 JPEG 格式、解码、声明尺寸和像素上限；损坏画面不能授权点击。仅对校准机型的竖屏（390 × 844 点），普通点击、主屏翻页和完成判断可忽略顶部 48 点状态栏，并在紧邻的一行最大通道差不超过 8 时排除该行 JPEG 淡色边缘；点击目标 y ≥ 49 点时才适用。输入、按键和发送始终检查全图，其他普通点击及完成判断的正文仍要求像素完全相同。

仅对通过双模型检查的 App 图标点击，正文及中心向四边各 24 点的目标区允许每个 RGB 通道差不超过 12 的轻微变化；目标区外每次比较另可容许最多 4 个图像像素的最大通道差为 13～16，目标区仍不允许超过 12。阈值和4像素上限是针对实测1～2个像素最大差14的演示余量，未经统计标定，也不限制12以内低对比度变化的面积，不能保证动态小组件均可通过或排除真实小变化。主屏翻页仍只允许路径外通道差不超过 8；x=78～312、y=688～712 点的拖动路径及校准误差范围要求完全相同，按实际 JPEG 尺寸缩放。超限变化不得直接授权，仅 App 图标首次移动后可进入上述一次语义复核；几何变化或图片无法解码仍取消。定位期间始终与原始决策画面比较，避免逐帧小变化累积后放行；不再屏蔽任何假定指针区域。发送仍检查全部像素。App 图标标记由本地已验证的 `tap_app` 候选生成，模型不能给普通点击添加此标记。不使用全图平均相似度，不整块忽略底部。圆屏确认时再次检查校准定位状态和画面，不宣称观察到真实落点。`assist` 是安全停止，不执行 HID；返回固定中文原因，不因画面变化掩盖原因。这项容差仍需真机验证。

Jev 模式连第一步打开 App 也经模型判断：若目标图标可见则提出点击；已支持翻页的圆屏先尝试安全的主屏翻页，其他情况可选择 Spotlight 宏或停止。原先「打开设置」「打开相机」直接使用宏的捷径仅保留在显式旧 Anthropic 模式中。任何模式都不能仅凭 HID 执行成功报告 App 已打开。

圆屏报告执行完成时，Mac 记录当时收到的最新帧编号；下一步必须等待比它更新的画面，不能使用按键执行期间的搜索中间态。 仅在成功点击 App 图标后，若“完成”判断的画面在提交前发生变化，或首次完成画面识别遇到明确的连接断开，Mac 最多等待一次更新帧，重新运行 Claude 画面识别与 Jev 判断，仍对新证据执行原来的严格像素检查；两种原因共用一次预算，HTTP 鉴权/限流、TLS、超时和格式错误不重试；不重复移动或点击，也不以旧判断或 USB 回报直接报告成功。复核等待有75秒总期限，复核所用识别帧最多40秒；帧过期、设备失联、配对或校准变化、再次变化或判断不明确时停止。此40秒证据期限仅适用于这条复核路径，帧编号表示接收顺序，不证明采集时刻。实测微信可能停在 Spotlight 搜索结果，不能把搜到图标当作已打开；模型需定位实际 App 图标再提出点击，新固件直接执行 App 图标点击，超出容差的画面变化仍取消。当前键盘宏仅在输入后等待 500 毫秒发送一次回车；微信上的回车效果和是否需要延长等待仍待真机验证。
