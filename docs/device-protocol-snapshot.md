# 圆屏与协调端协议：开发快照

基于 2026-11-03 本机 phone-pilot 圆屏工作区 `main/demo.c` 和 phone-pilot-ios 工作区 `demo/server.py` 的只读检查。两者均有未提交修改，指针闭环由另一个会话持续开发；这里不是冻结的协议版本，移植前需以其最终真机验证结果重新核对。

| 请求 | 当前用途 |
|---|---|
| `POST /pair` | 圆屏提交角色、配对码和能力列表，获得会话 token。当前能力包含主屏翻页、App 导航、语音反馈和指针验证。 |
| `POST /audio` | 圆屏上传 WAV；协调端调用语音识别并建立任务。 |
| `GET /next` | 圆屏轮询下一动作；响应可能含转写、解析结果、状态或错误。协调端分阶段执行指令理解、画面识别及决策。 |
| `POST /check` | 根据动作 ID 和最新画面检查动作仍然有效。 |
| `POST /pointer` | 指针校准/落点检查：按顺序发移动、上报执行并等待新帧；成功后才可执行点击或拖动。协议正被修改。 |
| `POST /result` | 圆屏按动作 ID 报告执行结果；重复动作需拒绝，执行后需等待新画面。 |

现有 iPhone 到 Mac 的 `POST /frame`、`POST /stop` 是抓屏上传协议。协调迁入手机后，帧应直接在进程内消费，无须将整帧发给圆屏。现有工作区的开发约束包括最近画面不超过 5 秒、任务最多 10 步、消息发送需确认；这些约束不是性能或真机成功率保证。

当前局域网使用明文 HTTP，配对码和 token 不提供传输加密。原样复用只能限于可信网络的开发联调；正式方案需要认证与加密。不得把固定配对码、设备地址或云端密钥提交到公开仓库。
